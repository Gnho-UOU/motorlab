## 지금까지 정해진 것
- 주제: EV 구동용 IPMSM 설계 → 효율맵 → 주행사이클 전비 통합 해석 도구. 기존 `Gnho-UOU/motor-analyzer`(유도기 교육용 시뮬레이터, 계산 근거·검증 부족)를 대체하는 새 프로젝트. motor-analyzer는 수정하지 않는다.
- 계산은 순수 Python 엔진, UI는 이후에 붙인다. 검증 통과 전 UI 확장 금지.
- 필수 범위 M1~M4(모터 모델, 운전 영역, 손실·효율맵, 주행사이클 전비). 확장 M5~M8은 순서대로.
- 최종 검증 기준: ORNL 프리우스 2004 구동모터(형상 보고서 ORNL/TM-2004/137 + 효율맵 측정 보고서). 이 모터는 "엔진 정답지"이고 설계 대상은 아니다. 설계 대상은 엔진 검증 후 현대 BEV급 사양으로 따로 정한다.
- FEA는 FEMM 4.2 + pyfemm. FEMM이 Windows 전용이라, Windows PC에서 `run_femm.bat` 더블클릭 한 번으로 계산 → CSV 저장 → GitHub 푸시까지 자동화한다(방법 1). 최적화 단계(M6)에서는 공유 폴더를 감시하는 작업 대기 모드(방법 2)를 검토한다.
- JMAG 등 상용 툴 리버싱은 하지 않는다. 나중에 연구실 라이선스를 쓸 수 있도록 FEA 부분은 교체 가능한 구조로 둔다.
- 일정(기획서 9장): P0 문헌·환경 준비(~12/6) → P1 엔진 코어 M1·M2(~1/3) → P2 손실·효율맵(~1/24) → P3 FEMM 연동·검증(~2/28) → G1 검증 관문 → P4 전비·UI 연결(~3/28) → 3/31 연구실 컨택 → P5 확장 → P6 정리.

## 2026-11-22 해결: 전체 모터 모델과 Br 보정
- **AGE 회전 문제는 다른 방법으로 해결했다.** 대칭 섹터·AGE 대신 전체 모터(360°, 48슬롯, 8극)를 공극까지 메시로 만들고 회전자를 기하학적으로 돌린다(`femm/prius_full.py`, `femm/validate_full.py`). 무부하 위상 오차 ≤ 0.7°, `λ(45°) = −λ(0)` 정확, 코깅 ±0.25 N·m. 점당 약 76초(8개 병렬). 원인(xfemm AGE의 어디가 틀렸는지)은 여전히 모른다. 자세한 내용은 `docs/FEA_OPTIONS.md` 3-3절.
- 스마트 메시가 기본 켜짐이고 xfemm Lua에 끌 명령이 없다. 저장한 `.fem`에 `[DoSmartMesh] = 0`을 넣으면 요소가 절반이 된다.
- **ORNL 잠금 토크 시험 모사:** 전류별 최대 토크가 실측(Fig. 3.10)의 0.99~1.09배, 토크-각도 곡선 7개가 영점 하나(와 거울 방향 가정)로 모두 맞는다(상관계수 0.991~0.996).
- **Br 보정(`1.24 → 1.056 T`)은 무부하 역기전력에만 맞췄고**, 독립 검증이 통과했다: 저속 필요 전류 엔진/측정 0.99(0.96~1.03), 250 A 잠금 토크 337 N·m(실측 337). 맵: `data/flux_maps/prius2004_fullmodel_Br1056_25A.csv`.
- **해결하지 못한 것(`docs/FEA_OPTIONS.md` 3-4절):** (1) 고속(> 2400 rpm) 필요 전류가 측정의 0.61~0.94배(중앙 0.72). 측정 전압이 육각파 한계에 있어 전압 가정은 원인이 아니고, 후보는 고속(큰 |id|)에서의 FEA d·q 자속 특성(교차 포화, 엔드턴 누설, 3D)이지만 확인하지 못했다. (2) 75 A 잠금 토크가 실측보다 13% 낮다. (3) AGE 오차의 원인.
- 다음 후보: 엔드턴 누설 인덕턴스 추정(해석식, 출처 필요), 맵 해상도(25 A → 12.5 A)와 메시 수렴, 상저항·철손을 넣은 효율맵(P2)과 ORNL 모터 효율 비교, 진짜 FEMM에서 같은 모델 교차 검증.

## 2026-11-22 G1 평가: 미달 (`docs/validation_report.md`)
- V1(T1~T8), V2(전력-부하각식 대체), V3(자속 기반 토크 대 FEA 토크 ±6%), V4 토크(잠금 토크 0.99~1.09배, 250 A에서 337 대 337 N·m)는 기준을 만족한다.
- **V4 효율이 미달이다.** ORNL Table B-1 모터 효율 382행과 비교: 전체 평균 +3.00%p(엔진이 높음), 주요 영역(1000~4000 rpm, 30~200 N·m) +3.07%p, 3%p 이내 52%, 고속(≥ 4000 rpm) +8.6%p. 저속·고토크는 맞음(`R20` 역산 구간과 겹쳐 독립 검증은 아님).
- 원인(실측만으로 분해): 측정의 "철손 + 기계손 + 기타"가 모델의 약 3배(속도에 따라 일정한 배율). 모델에 없는 손실(자석 와전류, PWM 고조파, 스트레이, 가공 철손 증가)이 후보이나 확인하지 못했다. 고속 전류 과소 예측이 일부 기여(고속 부족분의 약 15%). 계수 불확실성만으로는 주요 영역 평균이 +2.7~+3.9%p에서 움직인다. 철손 하나를 3배로 키워도 ≥ 4000 rpm에서 +6.2%p가 남는다. **어떤 계수도 결과에 맞추려고 조정하지 않았다.**
- **정확도 개선 시도(2026-11-22):** (1) 효율 최적 동작점(`objective="loss"` 구현, 독립 검증 테스트 포함)이 효율 불일치의 원인인지 확인 → 아니다(효율 오차 불변, 고속 필요 전류 비율 0.77 → 0.80). (2) 메시 수렴 확인 → FEA 자속 맵의 수치 오차는 약 0.1%라 남은 차이는 모델 오차다. (3) `Br` 보정이 기대는 "선간 실효값" 해석은 반대 해석이 `Br ≈ 1.8 T`(불가능)를 요구해 유일하게 가능하다. 자세한 내용: `docs/FEA_OPTIONS.md` 3-5절, `docs/validation_report.md`.
- 손실 계수의 출처와 불확실성: `data/benchmarks/prius2004_ornl.md` 9절. 효율 스크립트: `notebooks/03_prius_efficiency_validation.py`, 결과: `data/fea/prius2004_efficiency_validation.csv`.
- **사용자 결정 필요(기획서 9장):** G1 미달 상태로 P4(전비·UI)로 넘어갈지, 아니면 미달 원인(모델에 없는 손실, 고속 자속 특성)을 먼저 개선할지. 기획서 규칙은 "충족 전에는 다음 단계로 넘어가지 않음"이고 "미달 항목의 원인을 보고서에 기록"하면 관문을 닫을 수 있다고 적었다.

## 2026-11-22 정확도 개선: ORNL 해체 측정 (`docs/FEA_OPTIONS.md` 3-6절, `docs/validation_report.md` 재평가·원인 탐색)
- ORNL TM-2010/253(2004 Prius 해체 측정)과 대조해 입력을 바꿨다: 자석 18.9 × 6.5 mm(pyleecan과 같음), 공극 0.73 mm, 적층 83.6 mm, 상 저항 0.069 Ω(21 °C, 이전에 역산한 65 mΩ과 일치). 형상 `data/benchmarks/prius2004_geometry_teardown.json`, 맵 `data/flux_maps/prius2004_fullmodel_teardown_25A.csv`(Br 교정 1.06 T).
- Br 교정(시료 곡선 1.243 T보다 15% 낮음)은 독립 측정 세 개가 확인한다(무부하 역기전력, 공극 자속밀도 파형, 잠금 토크 75 A PM 성분). 15% 약한 이유는 모른다. **앞서 만든 "포켓 가설"(5.31 mm 자석이 6.5 mm 포켓 안에)은 해체 측정으로 틀렸음이 확인되어 폐기했다.**
- 손실 모델 이중 계산을 찾았다(TM-423 표 3.7 로터 손실에 무부하 철손 포함). 고치면 효율 오차가 오히려 커진다(+3.7%p). 정현파(인버터 없음) 900 rpm 시험(TM-2005/33)에는 잔여 손실이 없다 → 인버터 시험의 잔여 손실은 인버터 구동과 관련 가능성이 크다. 경험식(`ExcessLossParams`)으로 RMS 1.5%p지만 같은 벤치마크에 맞춘 보정이다.
- 미해결: 고속 필요 전류 엔진/측정 0.72~0.77(모델 전압이 한계의 0.75배), 높은 부하에서 정현파 시험 전류가 모델보다 작음(슬롯 면적·강판 포화 후보), 슬롯 면적 불일치(ORNL 철심 질량 기준 약 150 mm² 대 217.5 mm²).
- 사용자 결정: 경험식 보정은 G1 충족으로 인정하지 않는다(2026-11-22). P4는 시작하지 않았다.

## 2026-11-23 UI를 React 스튜디오로 교체 (P4)
- 첫 초안(바닐라 TS, 단순 2D 위주)을 버리고 `web/`를 React + TypeScript + react-three-fiber로 새로 만들었다. 이유: 부품 해부·단면·투어·드라이브 모드처럼 상태가 많은 인터페이스는 컴포넌트 구조가 필요하고, 데스크톱(Electron)으로 같은 코드를 감싼다. Rust가 없어 Tauri 대신 Electron을 골랐다.
- 3D: 출처 있는 치수(하우징 299 × 205 mm, 자석 83.1 × 18.9 × 6.5 mm, 엔드턴 38.1 mm 등)로 만든 실물형 모터. 해부 분해(부품별 순서), 부품 선택 시 카메라 비행과 부품 도감(`/api/parts`, 숫자마다 출처, 치수 출처 없는 부품은 "도식"), 단면(절단 위치 조절), FEA 자속선·자속밀도(`femm/export_flux_field.py` → `data/fea/flux_fields/*.json`).
- 엔진·API 추가: `engine/waveforms.py`, `CycleResult` 구간별 손실·효율·전류, `/api/operating_point`, `/api/parts`, `/api/flux`, 권선·하우징 치수. 테스트 추가(`tests/test_p4_waveforms.py`, `test_p4_api_ext.py`).
- 성능: 요청 시 렌더, 인스턴싱, 셰이더 적층 무늬·냉각수 입자, 적응형 해상도, Electron GPU 플래그. 속도 측정은 이 PC(헤드리스 브라우저 약 30 fps)에서만 했고 실제 GPU 앱 창의 fps는 측정하지 않았다.
- 데스크톱: `web/electron/`(개발 모드 점검 완료), 설치 파일(DMG/EXE) 생성은 설정만 했고 검증하지 않았다(`scripts/build_sidecar.sh`).
- 남은 것: 설치 파일 생성 검증, 부품별 더 정밀한 3D(치수 자료가 생기면), 하단 설계 A/B 비교, 데모 배포(외부 게시라 사용자 확인 필요), 컨택용 산출물.

- 자속 맵 121점을 만들었다(`data/flux_maps/prius2004_xfemm_delta0_25A.csv`, 25 A 간격, 약 8분). `FluxMapModel`로 읽어 엔진에 넣고 ORNL 실측과 **예비 비교**를 했다(`tests/test_v4_prelim_prius.py`, 계수 조정 없음):
  - 250 A MTPA 토크 362 N·m, 150 A에서 227 N·m: 실측 범위(337~400, 221~260) 안. 75 A에서는 109 N·m로 실측(118~140)보다 8~22% 낮다.
  - Table B-1 운전점에서 엔진이 예측한 필요 전류 / 측정 전류(실효값 × √2): 속도 ≤ 1900 rpm의 11점(토크 60~282 N·m)에서 **0.91~0.98**. 속도 > 2500 rpm에서는 **0.63~0.82**로 엔진이 전류를 적게 예측한다(Rs = 0, 철손 없음, 실제 DC 전압 강하 등 때문일 수 있으나 확인하지 못했다).
  - 무부하 자속은 ORNL 환산값보다 +21% 큰데 250 A 토크는 실측 범위 안이다. 이 둘이 서로 상쇄되었을 가능성이 있어 "검증 통과"라고 하지 않는다.
  - 비교 한계: 측정 전류의 상/선·첨두/실효 정의가 보고서에 없어 "상 실효값"으로 가정했다. 형상·자석·철심은 제3자 값이다. 상저항을 몰라 Rs = 0으로 했다. 맵은 회전자 한 위치(δ = 0)와 25 A 간격 선형 보간이다.
- 다음: 맵 해상도(25 A → 더 촘촘히)와 메시 수렴 확인, 상저항·철손을 넣은 효율맵(P2 `efficiency_map`)을 ORNL Table B-1의 모터 효율과 비교, 자석 Br 민감도(보정이 아니라 민감도 분석).
